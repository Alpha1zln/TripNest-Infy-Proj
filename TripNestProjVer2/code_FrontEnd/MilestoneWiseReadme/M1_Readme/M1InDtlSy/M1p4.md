And this is a very normal Spring dependency-cycle issue. Don't panic; we don't need to redesign everything.

Why this happened

Our dependency chain became:

SecurityConfig
    ↓
OAuth2LoginSuccessHandler
    ↓
AuthService
    ↓
PasswordEncoder
    ↓
SecurityConfig

💥 Cycle.

Why? Your PasswordEncoder is created inside SecurityConfig, while SecurityConfig itself needs the OAuth2LoginSuccessHandler.

So Spring says:

"I need SecurityConfig to create the handler, but I need the handler to finish creating SecurityConfig."

Quick clean fix

We'll tell Spring:

"Create AuthService only when the handler actually needs it."

Open:

OAuth2LoginSuccessHandler.java

Change the import:

import org.springframework.context.annotation.Lazy;

And change your constructor from:

public OAuth2LoginSuccessHandler(AuthService authService) {
    this.authService = authService;
}

to:

public OAuth2LoginSuccessHandler(@Lazy AuthService authService) {
    this.authService = authService;
}

That's the only change for now.

Why @Lazy works

Instead of:

Application starts
 ↓
Handler immediately needs AuthService
 ↓
AuthService needs PasswordEncoder
 ↓
Cycle ❌

Spring does:

Application starts
 ↓
Create Handler
 ↓
Keep AuthService ready for later
 ↓
Application starts successfully ✅
 ↓
Google login happens
 ↓
Handler actually calls AuthService

This is appropriate here because AuthService is only needed when the Google login succeeds.
